# Плейтест хаттамасы және түзетулер журналы
## History Detective — Тарихи дерек зерттеушісі (КЕЙС 07)

> **Маңызды ескерту.** 2-бөлімдегі кесте — **толтырылған үлгі**: мәндер баланс модельдеуі мен
> ішкі (сараптамалық) тестілеу негізінде болжанған. Комиссияға тапсырар алдында кемінде 5 нақты
> тестілеушімен сессия өткізіп, сандарды ойынның өзі жинайтын статистикадан (Аналитика → «JSON есепті
> экспорттау») көшіріп ауыстырыңыз. 4-бөлімдегі түзетулер журналы — әзірлеу кезінде **нақты орындалған** өзгерістер.

---

## 1. Плейтест әдістемесі

| Параметр | Мазмұны |
|---|---|
| Мақсат | Түсініктілік (UX), оқу нәтижелеріне жету, баланс (уақыт/қате), бейімделудің әсерін тексеру |
| Тестілеушілер | ≥ 5: 8, 10, 11 сынып оқушылары, студент, тарих мұғалімі, (қосымша) медиасауаттылық тренері |
| Сценарий | Нұсқаулықсыз ойынды бастау → 1-іс → 2-іс → (уақыт болса) 3-іс → сауалнама → қысқа сұхбат |
| Бақылау әдісі | «Дауыстап ойлау» (think-aloud), бақылаушы кедергі жасамайды, тек жазады |
| Объективті деректер | `user://history_detective_report.json`: уақыт, қателер, хронология ауытқуы, сенімділік дәлдігі, дәлелділік, кеңестер, бейімделу профилі |
| Субъективті деректер | UX/түсініктілік 1–5, қызығушылық 1–5, «не түсініксіз болды?», «не ұнады?» |
| Табыс критерийлері | ≥ 80 % тестілеуші 1-істі шешеді; UX ≥ 4.0; 1-істің орташа уақыты 6–9 мин; бейімделу профилі тестілеушілер арасында ажыратылады |

### Сауалнама (сессиядан кейін, 1–5)
1. Не істеу керек екені бірден түсінікті болды ма?
2. Карточкадағы сөйлемді белгілеу механикасы түсінікті ме?
3. Хронология тақтасын басқару ыңғайлы ма?
4. Қате жауаптардың түсіндірмесі пайдалы болды ма?
5. Ойын тест емес, «тергеу» сияқты сезілді ме?
6. (Ашық) Ойыннан кейін фейк тарихи постты қалай тексерер едің?

## 3. Бақылау чек-парағы (бақылаушыға)
- [ ] Брифингті оқыды ма, әлде бірден жапты ма?
- [ ] Карточкадағы сөйлемді басуды өзі тапты ма (қанша секундта)?
- [ ] «Салыстыру» режимін өз бетімен қолданды ма?
- [ ] Хронологияда ▲/▼ қолдануда қиналды ма?
- [ ] Кеңесті қай кезеңде алды?
- [ ] Түсіндірмелерді оқыды ма (оверлейде ≥ 5 секунд)?
- [ ] Қорытындыда өзі 1–2 қойған дереккөзді таңдады ма?

## 4. Түзетулер журналы (мәселе → себебі → өзгеріс → нәтиже)

| № | Мәселе | Себебі | Өзгеріс | Нәтиже (тексерілген) |
|---|---|---|---|---|
| 1 | «Бәрін белгілеу» стратегиясы белгілер кезеңінде 67–71 ұпай берді | Артық белгі айыппұлы маңызды белгілер санына нормаланған еді | Формула: `табылған/маңызды − артық/бейтарап` | «Бәрін белгілеу» = 0 ұпай; тест `clue_score(5,4,5,4) == 0` |
| 2 | 2–3-істе сарапшы бір артық белгі үшін −25 алды | Бейтарап сөйлемдер тым аз (4–5), кейбір карточкада барлық сөйлем маңызды болды | Әр карточкаға 1–3 бейтарап сөйлем қосылды (бейтарап: 6 / 9 / 9) | Сарапшы белгі ұпайы 68 → 82; мәтін «шынайырақ», айғақ іздеу күрделенді |
| 3 | Кездейсоқ реттелген хронология айтарлықтай ұпай алуы мүмкін еді | Сызықтық шкаланың нөлі максималды ауытқуға байланған | Нөлдік нүкте — кездейсоқ реттің күтілетін ауытқуы `(n²−1)/3` | Кездейсоқ рет ≈ 24–27 / 300 (4000 модельдеу) |
| 4 | Жылдам «болжау» уақыт бонусымен марапатталуы мүмкін еді | Бонус тек уақытқа тәуелді | Бонус тек дұрыс қорытынды + дәлелділік ≥ 70 болғанда | Тест: `time_bonus(..., quality=60) == 0`; B-салыстыру «импульсивті» профильді бөлек анықтайды |
| 5 | Прогресті тазалау терезесінде «бас тарту» жоқ еді | Оверлейде бір ғана батырма болған | Оверлейге міндетті емес екінші батырма («Бас тарту») қосылды | Қате тазалау мүмкін емес |
| 6 | 3-істе жасырын даталар әлсіз ойыншыны тұйыққа тірейді (T1, T4 үлгісі) | Уақыт маркерлері тек мәтінде | `chrono_support` бейімделуі: ⏱ маркерлер көкпен, жасырын даталарға «Бағдар» | Хронология қатесі > 30 % + сенімділік ≥ 75 % профилінде автоматты қосылады |
| 7 | Сөйлемді басуға болатыны бірден байқалмайды (T1 үлгісі) | Мәтін кәдімгі абзац сияқты көрінеді | Карточкада нұсқау жолы «сөйлемді басып белгіле», курсор «қол» белгісіне ауысады, детектив дәптері бос кезде кеңес береді | Ашық мәселе: нақты плейтестте тексеру керек |
| 8 | Тарихи сезімтал тақырыптарда «жалған құжаттың» шынайы деп қабылдану қаупі (T5 ұсынысы) | Модельдік мәтіндер нақты құжатқа ұқсайды | Әр брифингте және басты мәзірде «модельдік үзінді» ескертуі; README мен GDD-де дереккөз саясаты | Комиссияға этикалық негіздеме дайын |
| 9 | Грамматикалық қате «Ісді ашу» | Септік жалғауы | «Істі ашу» | Түзетілді |
